## 哪些内容进入 GitHub

发布：代码、配置、方法说明、来源/实验索引、经审核的精简指标与案例、分桶 CSV、可公开截图和图表。
不发布：原始数据集、视频、模型权重、optimizer/RNG 张量、完整原始 console/history/逐样本预测，
或密码、密钥、整套环境变量。公开 JSON 仅为审计元数据/权重项名称，不含实际权重值。
上游数据与模型许可继续适用；“可访问”不等于可以重新分发。

GitHub 不是权重和完整原始证据的备份。本任务目前没有声称已完成独立磁盘、异机或云端备份；
若需要新增存储、付费服务或对外上传，先由用户决定目的地、访问范围与预算。
不能因报告材料已提交 Git，就删除唯一服务器权重或逐样本输出。

## 硬链接、符号链接和空间数字

共享 `.venv`、原始输入和部分缓存使用链接，继承 LLM 产物在逐文件 SHA 核对后合并为相同 inode。
初始归档以复制并核验实现；后续这部分内容相同的语言产物节省存储，但不是独立物理副本。
硬链接/符号链接都不是灾备：在共享 inode 上原地修改会影响多个路径，符号链接的目标删除会失效。
因此归档内容只读；不得向共享权重路径原地写入、格式转换或修复。
训练器写临时文件后原子替换路径；审计硬链接固定旧 inode，保证当前保留快照不随新保存变化。

`df` 反映文件系统可用空间，`du` 反映所遍历文件占用，逻辑文件大小总和可能重复计算硬链接，
也可能漏掉符号链接目标。不要简单相加多个子目录的 `du` 当作独立物理占用。
先前默认 Arrow 诊断副本已按 SHA 改为引用项目缓存；不重复物化相同数据，不清理其他项目缓存。

2026-10-24 17:50 UTC 的一次观察：数据盘剩余约 23 GB，当前修复 run 的目录 `du -sh` 约 3.1 GB。
这只是当时的空间，不是全部阶段所需空间的承诺；共享盘其他任务会改变余量。
新建额外快照、缓存或重放输出前需重新核验空间，不因此启用定时监控。

## 空间不足时的顺序

1. 只读确定具体挂载盘、项目自身目标和引用关系，区分 logical size 与实际占用；不扫描或更改其他项目。
2. 优先复用已校验资产和缓存，避免重新下载或建立重复输出；不得先删证据再检查缺了什么。
3. 清理候选必须列出精确路径、文件用途、SHA/关联 run、是否唯一原件、恢复来源与预计释放空间。
4. 涉及重要数据/权重/日志/快照或不明所有权时先请求用户决定，不擅自搬走、压缩覆盖或删除。
5. 若保存失败，保留错误和已有原子恢复点，核验完整性后再决定恢复步骤；不靠反复重启掩盖空间问题。

不建立自动清理任务，不停止其他项目，也不以“已经训练完成”为理由放宽证据保留。
