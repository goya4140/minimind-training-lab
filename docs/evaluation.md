# 评估协议

## 通用门禁

所有模型必须通过：

1. 模型前向与 loss 单元测试；
2. 固定 seed 的训练冒烟测试；
3. checkpoint 保存、重新加载一致性；
4. 输入输出张量和 loss mask 检查；
5. 与训练集分离的评估集。

## LLM

- Validation loss、Perplexity、Bits Per Byte；
- 固定基础知识、指令跟随、重复生成测试；
- 每个固定样例的生成耗时与 tokens/s；
- 生成样例必须同时展示成功和失败案例。

Pretrain 与 SFT checkpoint 使用完全相同的文本留出集、tokenizer 和固定提示分别评估。最终报告并排
展示 PPL 变化与生成结果，避免只凭 SFT 训练 loss 判断指令微调是否有效。

## VLM

- 固定图像描述、VQA 与视觉幻觉检查；
- 固定图像提示词记录关键词召回率，作为轻量、可复现的词面代理指标，不是语义正确率下限；
- 固定双图顺序和指代测试；
- 单图案例替换为固定错图，双图案例反转图像顺序，报告关键词召回差与回答变化率；
- 重新运行 LLM 文本评估，测量语言能力遗忘。

当前 CUDA 固定实现的口径（`scripts/train_vlm.py`、`scripts/evaluate_vlm.py`、
`src/minimind_lab/evaluation/vision.py`）需要在结果中明确：

- 训练排除过滤后数据集末尾 512 行；阶段结束验证使用这 512 行，而独立 evaluator 默认只取
  其中最后 128 行。两者都不用于训练，但不是两个相互独立的测试集，样本量不同不能直接相减。
  它们是行级留出，未证明跨集合图像或语义去重，不宣称无相似内容泄漏。
- 固定展示共 7 题：6 道单图、1 道双图。原评估 JSON 保留全部正常/反事实回答；
  单图错图由下一题首图确定，双图将输入图像反转，仍对照原关键词，不是新输入自身的正确率。
- 关键词仅检查子串出现，不验证否定、对象绑定、事实正确性或幻觉。双图题即使顺序完全错误，
  只要提到了全部关键词仍可能得满分。必须阅读实际回答，不能把该指标称为图像顺序准确率。
- 回答改变仅说明对输入变化敏感；两次都错也可能改变，两次一样也可能只是复读。
  原汇总混合单图错图和双图倒序，报告时分别说明这两种扰动，不将混合平均解释为纯顺序消融。
- 图像验证 loss 是各 batch 标量 loss 的算术平均，不是跨样本/监督 token 加权 NLL。
  固定 evaluator 跳过非有限 batch，但没有返回跳过数量；不能仅因最终数字有限就断言所有
  batch 均有限。若需此断言，必须有额外逐 batch 核验，不静默改写已固定评分。
- VLM 原评估默认最多生成 96 个新 token；原 LLM 固定生成 80、视频 48。文本留出集的
  NLL/PPL 可以在相同样本/token 口径下比较，但生成长度、复读率和耗时不能作为严格同条件比较。

VLM 和 Video-Omni 的纯文本回归使用与 LLM 相同的 held-out 文本、tokenizer、loss/PPL/BPB
计算和固定提示。最终报告同时展示 PPL 变化与同一提示的三模型回答，用于区分“多模态能力增加”
与“语言能力被破坏”。

## Video-Omni

- 固定 250 条 held-out QIVD test 的 assistant-only loss；
- 在固定前 100 条 test 样本上报告 normalized exact match、reference containment 与 token F1；
- 按 QIVD category 分组报告 token F1，避免总体均值掩盖弱项；
- 对相同视频倒序 8 帧，报告 loss 差值、token F1 差值和回答变化率；
- 保存至少 12 组问题、参考答案、正常帧回答、倒序帧回答作为定性样例；
- 报告单样本生成耗时，并重新运行 LLM 文本评估检查能力遗忘。

此外，`scripts/generate_temporal_benchmark.py` 固定 seed 生成 160 个无文字提示的视频，均分为
水平移动、垂直移动、尺寸变化和事件先后四类。该集合不参与训练；对 160 条全部计算正常/倒序 loss，
对 160 条全部生成正常/倒序答案。倒序会反转每道题的正确语义，因此 normal-minus-reversed 指标比
普通真实视频倒序更容易解释。

现有倒序评估始终使用原始视频的参考答案：它检验原答案在顺序扰动后是否仍被支持，**不计算倒序
视频自身正确答案的准确率**。正常输入优于倒序输入可支持顺序敏感性，但不能单独证明正确的时序
推理；分数相同也可能来自两种回答都错误或答案词袋重叠。若不能建立稳定的顺序相关正确行为，
最终报告必须写成“时序能力尚未验证”，不能仅凭视频 QA 文本分数宣称视频理解成功。后续可使用
VisualBench 等专门要求跨帧推理的外部数据作第二重检验，但不与 QIVD 训练集混用。

最终报告必须注明模型规模、冻结外部模块规模、数据范围与硬件，不能只展示训练 loss。

固定版本视频 evaluator 对 100/160 条生成全部计分，但汇总仅留前 12 条原始回答；完整逐样本留存
通过独立的[视频证据重放工具](../reporting/video-evidence-replay.md)补齐。原固定评估文件不覆盖，
重放使用独立 eval ID，明确其额外执行时间与来源，不将工具单元测试计作已完成模型评估。
